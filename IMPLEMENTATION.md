# Terraform Provider for Stalwart Email Server

## 概要 (Overview)

このプロジェクトは、[Stalwart Email Server](https://stalw.art/)のためのTerraform Providerです。OpenAPI仕様からの自動生成コードを使用して実装されています。

This project is a Terraform Provider for [Stalwart Email Server](https://stalw.art/), implemented using auto-generated code from the OpenAPI specification.

## 実装アプローチ (Implementation Approach)

### OpenAPIベースのコード生成 (OpenAPI-based Code Generation)

このプロバイダーの最大の特徴は、**OpenAPI仕様から自動生成されたAPIクライアント**を使用していることです。

The key feature of this provider is the use of an **auto-generated API client from the OpenAPI specification**.

#### メリット (Benefits)

1. **型安全性** - 全てのAPIリクエスト/レスポンスが型チェックされる
2. **API一貫性** - 公式OpenAPI仕様に完全準拠
3. **保守性** - API変更時は仕様を更新して再生成するだけ
4. **エラー削減** - 手動コーディングによるミスを最小化

1. **Type Safety** - All API requests/responses are type-checked
2. **API Consistency** - Fully compliant with official OpenAPI spec
3. **Maintainability** - Just update spec and regenerate on API changes
4. **Error Reduction** - Minimize manual coding errors

### コード生成ワークフロー (Code Generation Workflow)

```bash
# 1. OpenAPI仕様を取得 (Get OpenAPI specification)
curl https://raw.githubusercontent.com/stalwartlabs/stalwart/main/api/v1/openapi.yml -o openapi.yml

# 2. コード生成 (Generate code)
make generate  # Uses oapi-codegen

# 3. ビルド (Build)
make build

# 4. インストール (Install locally)
make install
```

### コンポーネント (Components)

#### 1. Auto-Generated Client (`internal/client/client_gen.go`)

- **生成元**: Stalwart OpenAPI Specification v1
- **ツール**: oapi-codegen v2.5.1
- **サイズ**: 282KB, 9000+ 行
- **内容**:
  - 全APIエンドポイントのクライアントメソッド
  - リクエスト/レスポンス型定義
  - パラメータ構造体

#### 2. Authentication Wrapper (`internal/client/auth.go`)

- OAuth 2.0 トークン管理
- 自動トークン更新（50分有効期限）
- Basic認証からBearer認証への変換
- リクエストインターセプター

#### 3. Provider Resources

**`stalwart_principal`** - ユーザー、グループ、ドメイン、リストの管理
- Create: POST /principal
- Read: GET /principal/{id}
- Update: PATCH /principal/{id}
- Delete: DELETE /principal/{id}

**`stalwart_dkim_signature`** - DKIMシグネチャの作成
- Create: POST /dkim
- 注意: API仕様上、Read/Delete エンドポイントが存在しない

#### 4. Data Sources

**`stalwart_principals`** - プリンシパルの一覧取得
- GET /principal with filtering

## 使用例 (Usage Examples)

### プロバイダー設定 (Provider Configuration)

```hcl
provider "stalwart" {
  endpoint = "https://mail.example.org/api"
  username = "admin"
  password = var.stalwart_password  # 環境変数推奨
}
```

### ユーザー作成 (Create User)

```hcl
resource "stalwart_principal" "user" {
  type        = "individual"
  name        = "john"
  description = "John Doe"
  quota       = 10737418240  # 10GB
  emails      = ["john@example.org"]
  roles       = ["user"]
}
```

### DKIMシグネチャ (DKIM Signature)

```hcl
resource "stalwart_dkim_signature" "example" {
  algorithm = "Ed25519"
  domain    = "example.org"
  selector  = "default"
}
```

## 技術的な課題と解決策 (Technical Challenges and Solutions)

### 1. OpenAPI仕様の重複エンドポイント

**問題**: `/reload` と `/reload/` が両方存在し、コード生成エラー

**解決**: OpenAPI仕様から重複エンドポイントを削除

```bash
sed -i '1947,1970d' openapi.yml  # Remove duplicate /reload/
```

### 2. 認証フロー

**課題**: Basic認証 → OAuth トークン → Bearer認証の3段階

**解決**: AuthenticatedClient ラッパーで透過的に処理
- 初回リクエスト時に自動認証
- トークン有効期限管理
- 全リクエストに自動的にBearerトークン追加

### 3. 型システムの違い

**課題**: OpenAPI (JSON) ↔ Terraform (types.String, types.List)

**解決**: 
- 自動生成された型を使用
- Terraform型への明示的変換
- ポインタ型の適切な処理

## APIの制限事項 (API Limitations)

### DKIM Signature リソース

OpenAPI v1仕様には以下のエンドポイントが存在しません：

- `GET /dkim/{id}` - DKIM設定の取得
- `DELETE /dkim/{id}` - DKIM設定の削除

**影響**:
- Readオペレーション: 状態を維持するのみ（drift検出不可）
- Deleteオペレーション: Terraformステートから削除のみ

**回避策**:
- 完全なライフサイクル管理には `/settings` APIを使用
- 将来のバージョンでsettingsリソースを実装予定

```bash

# oapi-codegenのインストール
go install github.com/oapi-codegen/oapi-codegen/v2/cmd/oapi-codegen@latest

# ビルド
make build
```

### コード再生成 (Regenerate Code)

OpenAPI仕様を更新した場合：

```bash
# 1. 最新の仕様を取得
curl https://raw.githubusercontent.com/stalwartlabs/stalwart/main/api/v1/openapi.yml -o openapi.yml

# 2. 必要に応じて修正（重複エンドポイントなど）

make generate

# 4. ビルド確認
make build
```
